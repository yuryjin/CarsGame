# Проверки CarsGame

В проекте уже есть Unity Test Framework: EditMode проверяет расчёты, экономику,
сохранения и отдельные компоненты; PlayMode — жизненный цикл объектов, гонки,
ввод и переходы интерфейса. Браузерные проверки WebGL лежат рядом в `*.mjs`.

## Обычный запуск (Linux)

Из корня проекта:

```bash
Tools/qa/tests.sh edit       # быстрые проверки перед каждым изменением
Tools/qa/tests.sh play       # интеграционные сценарии в Unity
Tools/qa/tests.sh all        # последовательно EditMode, затем PlayMode
```

Без аргументов запускается EditMode. При ошибке EditMode команда `all`
останавливается. Старые `edit-tests.sh` и `play-tests.sh` остаются рабочими.
Первый запуск готовит отдельную копию проекта и может занять несколько минут.

Один тест или несколько классов:

```bash
Tools/qa/tests.sh edit 'SaveMergeInvariantTests;RaceCupBoundaryTests'
Tools/qa/tests.sh play 'CupProgressionPlayTests'
```

Редактор основного проекта можно оставить открытым: тесты выполняются в копии,
а PlayerPrefs — в отдельном профиле. Новые `.meta` копируются обратно только для
существующих исходных файлов без `.meta`. Запуски этих трёх команд на одной копии
сериализуются файловой блокировкой. Другие QA/build-скрипты этой блокировки не
используют: им нужна отдельная `SIM`.

## Окружение и результаты

Нужны Unity **6000.5.9f1** с рабочей лицензией, Bash, Python 3, `rsync`, `flock`,
`taskset`, `timeout`, `rg`; для полного PlayMode — `xvfb-run` и Vulkan-драйвер GPU.
Звук должен идти в `AgentSink` через уже заданный `PULSE_SINK`.

Основные переменные:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `UNITY` | `$HOME/Unity/Hub/Editor/6000.5.9f1/Editor/Unity` | Путь к редактору |
| `CG_WORK` | `/tmp/cars-qa` | Копия проекта, логи и XML |
| `SIM` | `$CG_WORK/sim` | Изолированная копия проекта |
| `CG_QA_CONFIG_HOME` | `$CG_WORK/config` | Изолированные настройки/сохранения |
| `CG_CPU_SET` | `0-3` | Разрешённые ядра CPU |
| `CG_TEST_TIMEOUT` | `1800` | Лимит секунд на один запуск Unity |
| `CG_TEST_TAG` | `edit` / `play` | Имя отчётов; для `all` добавляется `-edit` / `-play` |

```bash
CG_WORK=/tmp/cars-my-tests CG_TEST_TAG=regression Tools/qa/tests.sh all
```

Результаты по умолчанию: `/tmp/cars-qa/edit.xml`, `edit.log`, `play.xml`,
`play.log`; вывод запуска сохраняется в `*.runner.log`, ошибки Xvfb — в
`*.xvfb.log`. Отчёт перечисляет passed/failed/skipped/inconclusive. Команда
возвращает ненулевой код при ошибке Unity, проваленном тесте, отсутствии или
повреждении XML, пустом выборе тестов либо отсутствии выполненных тестов.
Обычные skipped видны в отчёте; они не означают проверенное поведение.
Таймаут Unity возвращает `124` (при принудительном KILL возможен `137`).

Не используйте `CG_NOGRAPHICS=1` для полного PlayMode: гараж создаёт
RenderTexture. Эта настройка предназначена только для заведомо совместимых
фильтров. В Unity UI также можно запустить наборы через Test Runner, но некоторые
тесты меняют PlayerPrefs — для них предпочтителен изолированный CLI-профиль.

Проверки самого механизма запуска не требуют Unity:

```bash
python3 -m unittest discover -s Tools/qa -p 'test_unity_runner.py' -v
```

## Что добавлено в этом проходе

- `SaveMergeInvariantTests`: сходимость прогресса при шести порядках доставки
  трёх снимков и двух группировках merge; повторная синхронизация с устаревшими
  снимками через сериализацию; независимость изменяемых данных; монотонный
  прогресс при одинаковых timestamp. Сценарии используют фиксированные seeds.
  Выбор настроек при равном timestamp намеренно не объявляется коммутативным.
- `RaceCupBoundaryTests`: все 512 комбинаций масок звёзд каждого из трёх кубков,
  отсутствие любого финиша, посторонние события/биты звёзд, сохранение всех
  косметических наград после перезагрузки без повторной выдачи.
- `test_unity_runner.py`: XML-проверка и запуски CLI с подставным Unity-процессом,
  включая коды ошибок, старые отчёты, фильтры и последовательный запуск наборов.

Число тестов не является процентом покрытия кода. Эти проверки не заменяют
проверки физики в PlayMode и реальные сценарии в WebGL.

## Браузерные проверки

Любой браузерный сценарий запускать только через машинную очередь:

```bash
webtest --check-gpu
webtest -t 900 -- node Tools/qa/browser-smoke.mjs
```

Сначала прочитайте настройки конкретного `*.mjs`: ему может понадобиться
собранный WebGL, локальный сервер и адрес страницы. Chrome должен получать
`WEBTEST_CHROME_ARGS` с NVIDIA Vulkan, а браузер закрываться в `finally`.
Не подменяйте эти проверки CPU-рендерингом SwiftShader.

## Когда запускать

Перед локальным коммитом — EditMode. При изменениях игрового поведения —
соответствующие PlayMode-классы. Перед выпуском — оба полных набора и браузерные
сценарии затронутых функций на собранном WebGL. CI может вызывать ту же команду
`Tools/qa/tests.sh all` на лицензированном Linux runner с GPU и сохранять XML/логи;
подключение CI не выполнено этим изменением.
