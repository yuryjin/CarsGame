# Слабые места CarsGame и план закрытия

Срез: **2026-10-25**, база Git `634362a` + незакоммиченные изменения рабочего дерева. Это выборочный статический аудит собственного кода, QA-скриптов и журналов; Unity, браузер, реальный SDK и устройства в рамках этого аудита не запускались. Работа над игрой продолжается: перед исправлением сверять актуальный код и последние записи журнала.

Источник истины по открытым рискам — этот файл. Graphify хранит его понятия и связи с кодом; граф не заменяет проверку реализации. Статусы: **open** — требуется работа; **verification** — реализация/частичные проверки есть, общего доказательства закрытия нет; **closed** — приложено доказательство по указанному критерию. P1 — до релиза; P2 — следующий цикл надёжности; P3 — плановый долг. Оценки S/M/L — относительный объём, не обещание срока.

## CG-RISK-001 — отпускание сенсорного управления

**Область / серьёзность:** Input / High. В [журнале](ImprovementCycle-2026-10-25.md), запись «Touch-browser7», комбинация large+left на ширине 640 оставляет `steer=-1`, `padLeft=1` при `touches=0` после DOM touchend обоих пальцев. Это результат старшего проверенного браузерного кандидата 7, а не утверждение о воспроизведении на любом последующем состоянии.

**Код:** [TouchButton](../../Assets/CarsGame/Game/Input/TouchButton.cs), [TouchControlsPresenter](../../Assets/CarsGame/Game/Input/TouchControlsPresenter.cs), [touch-preferences.mjs](../../Tools/qa/touch-preferences.mjs). В текущем TouchButton уже есть физическое восстановление отпускания и диагностика; журнал прямо отмечает, что прежней защиты недостаточно. Влияние — машина продолжает поворачивать без касания.

**Закрытие:** установить цепочку DOM → Input System → виртуальная кнопка; добавить регрессию и добиться нулевого steer/кнопок после release/cancel/потери фокуса для обеих сторон, размеров кнопок, нескольких пальцев на одной/разных кнопках и переключения touch/клавиатуры. Сохранить браузерные snapshots до/после на одном кандидате; дополнить физическим телефоном (CG-RISK-003).

## CG-RISK-002 — приёмка реального SDK

**Область / серьёзность:** Platform / High, пробел проверки. [Чек-лист Yandex](../Release/Yandex/checklist.md) прямо ограничивает текущие доказательства mock SDK; `multiplayer.sessions` не подтверждён реальной площадкой. Влияние — ошибки интеграции могут проявиться только после загрузки черновика.

**Код/границы:** [YandexPlatform](../../Assets/CarsGame/Platform/Yandex/YandexPlatform.cs), [cars-platform.js](../../Assets/WebGLTemplates/Yandex/TemplateData/cars-platform.js), [GameFlow](../../Assets/CarsGame/Game/Flow/GameFlow.cs).

**Закрытие:** на конкретном ZIP/SHA-256 пройти чек-лист в черновике площадки: ready/gameplay markers, реклама и единственная награда, pause/audio, guest→account, облако при отказах/повторном входе, best_e1…best_e20/best_m1/daily, реальные sessions и блокировка QA-команд. Приложить результаты каждого пункта. Mock/browser PASS не закрывает этот риск; аудит сам ничего не публикует.

## CG-RISK-003 — устройства, производительность и память

**Область / серьёзность:** Performance / High как риск релиза, не подтверждённая утечка. [Журнал 25 октября](ImprovementCycle-2026-10-25.md), «Visual-browser6», сообщает неоднозначное сравнение FXAA под посторонней нагрузкой: p95 на 1280 — 29/32 мс после против 31/17 мс до. Физические телефоны и контроллер не проверены. [Endurance](Endurance-2026-10-24.md), «Locale-lifetime20» и «Shipping20», показывает стабильные счётчики Unity в конкретной сборке, но не измеряет всю память браузера/WASM.

**Код/проверки:** [visual-quality.mjs](../../Tools/qa/visual-quality.mjs), [endurance.mjs](../../Tools/qa/endurance.mjs), [ResourceLifetimePlayTests](../../Assets/CarsGame/Tests/PlayMode/ResourceLifetimePlayTests.cs), [сцена](../../Assets/Scenes/SampleScene.unity).

**Закрытие:** согласовать минимальные устройства и бюджеты FPS/p95/памяти; повторить FXAA-сравнение без конкурирующей нагрузки на одинаковом маршруте; на физических телефонах проверить touch, safe area, звук/фон, не менее 10 циклов гонка→результаты→гараж после прогрева. Записать модель/ОС/браузер, память процесса и WASM отдельно от Unity. Недоступная метрика остаётся «не измерена»; рост одного Editor-счётчика не объявлять утечкой.

## CG-RISK-004 — наблюдаемость ошибок локального сохранения

**Область / серьёзность:** Persistence / High. [PlayerPrefsSaveStore.Write](../../Assets/CarsGame/Platform/PlayerPrefsSaveStore.cs) поглощает все исключения `SetString`/`Save`, а `ILocalSaveStore.Write` возвращает void. [SaveService.MarkDirty/FlushAsync](../../Assets/CarsGame/Core/Save/SaveService.cs) не получает подтверждения локальной записи; при отсутствии cloud FlushAsync возвращает Success. Влияние — UI/вызывающий код не могут отличить сохранение от неудачи, особенно offline.

**Закрытие:** ввести явный результат записи/состояние ошибки и восстановимый путь повторения; не сообщать об успешной локальной сохранности при отказе. Проверить инъекцией отказа хранилища отсутствие облака, последующее восстановление и перезапуск. [PlayerPrefsSaveStoreTests](../../Assets/CarsGame/Tests/EditMode/PlayerPrefsSaveStoreTests.cs) сейчас проверяет отсутствие значения и нормальный round trip, но не отказ записи.

## CG-RISK-005 — восстановление повреждённого локального сейва

**Область / серьёзность:** Persistence / Medium. [SaveMigrator.Parse](../../Assets/CarsGame/Core/Save/SaveMigrator.cs) возвращает Corrupt/null. [SaveService](../../Assets/CarsGame/Core/Save/SaveService.cs) запоминает LastLocalStatus, но блокирует MarkDirty только при NewerVersion. Поэтому при corrupt local и отсутствии пригодного cloud следующая запись может заменить исходный blob новым профилем. Резервирование исходного blob в просмотренном пути отсутствует. Это отдельный вопрос от уже исправленной защиты новой версии.

**Закрытие:** определить продуктовую политику восстановления; сохранить исходные данные до сброса, сообщить о восстановлении/невозможности чтения и не выдавать пустой профиль за найденный прогресс. Тесты: corrupt local + offline, corrupt local + valid cloud, отказ чтения (Read сейчас тоже превращает исключение в пустую строку), последующая запись и повторный запуск.

## CG-RISK-006 — актуальность изолированной QA-копии

**Область / серьёзность:** Builds/tests / Medium. В [common.sh:ensure_sim](../../Tools/qa/common.sh) Packages и ProjectSettings копируются при первом создании SIM; при повторном использовании синхронизируются только Assets и `ProjectSettings.asset`. Изменения manifest/lock, Input/Quality/Graphics/EditorBuildSettings могут не попасть в тест или билд. Это может сделать результат нерелевантным рабочему дереву.

**Закрытие:** синхронизировать все входные Packages/ProjectSettings или отклонять устаревший SIM; сохранять изоляцию Library/Pipeline и профиля. Проверить на временной копии изменением manifest и настройки вне ProjectSettings.asset, сверить хэши до запуска. [freeze-source.py](../../Tools/qa/freeze-source.py) фиксирует реальные входы, но сам не исправляет их актуальность.

## CG-RISK-007 — единое доказательство финальной интеграции

**Область / серьёзность:** Release validation / High, пробел проверки. [Журнал](ImprovementCycle-2026-10-25.md) содержит 390/390 EditMode и 85/85 PlayMode на более ранних snapshots, браузер ghost11 до объединения мешей, 79/80 practice + отдельный Warden PASS. Позднее добавлены reward breakdown, hybrid pause и touch-диагностика; на срезе журнала Edit14/candidate14 ещё выполняются. Частичные успехи не доказывают целостность последнего дерева.

**Закрытие:** заморозить один snapshot; приложить source/test manifests, XML полных EditMode/PlayMode, единый зелёный 20×4 practice, WebGL build/ZIP hash и браузерные проверки touch, rewards, pause/settings, ghost, save reload и endurance именно этого runtime. У каждой проверки указать кандидат/хэш. Переоткрывать при изменении затронутого поведения. Это gate перед поставкой, не требование прогонять весь проект ради правки документации.

## CG-RISK-008 — концентрация ответственностей

**Область / серьёзность:** Architecture / Medium; подтверждённая структура, предполагаемая стоимость изменений. [GameFlow.cs](../../Assets/CarsGame/Game/Flow/GameFlow.cs) (~707 строк на срезе) связывает переходы, гонку, практику, паузы, рекламу, выплаты и рекорды. [MenuScreens.cs](../../Assets/CarsGame/Game/UI/MenuScreens.cs) (~945 строк плюс partial-файлы) строит меню и обрабатывает разные сценарии. Сам размер не доказывает ошибку; partial разбивает файл, но сохраняет общее состояние и связанность.

**Закрытие:** постепенно выделять тестируемые правила выплат/результатов, навигацию и переходы практики за узкими границами; сначала зафиксировать существующее поведение. Не переписывать проект целиком. Проверять FinishTransition, PauseSettings, Practice, RewardPresentation и SaveCompatibility после каждого затронутого шага. Имеющиеся Core/Game/Platform assembly boundaries сохранять.

## CG-RISK-009 — воспроизводимость окружения QA

**Область / серьёзность:** Tooling / Medium. [browser-smoke.mjs](../../Tools/qa/browser-smoke.mjs) и другие probes по умолчанию импортируют playwright-core из `/home/user/gstack/node_modules`; [common.sh](../../Tools/qa/common.sh) задаёт путь Unity в домашнем каталоге и Python 3.10 site-packages. Override-переменные есть, общего закреплённого bootstrap QA-зависимостей нет среди просмотренных Tools/qa. Влияние — новый разработчик/runner не может воспроизвести проверку только из checkout.

**Закрытие:** описать и закрепить Node/Playwright/Python зависимости и установку webtest/Chrome/Xvfb/Vulkan; добавить preflight с понятными ошибками и переносимыми путями. Проверить инструкции в чистом окружении. Сохранить NVIDIA Vulkan, очередь webtest, finally close и AgentSink; не заменять их незаметно на SwiftShader.

## CG-RISK-010 — достоверность EditMode gate

**Область / серьёзность:** Tests / Medium. [edit-tests.sh](../../Tools/qa/edit-tests.sh) проверяет exit Unity, но Python-блок только печатает total/passed/failed и не возвращает ошибку при failed>0 или отсутствии совпадения заголовка. Затем `grep ... || true` может замаскировать ошибку самого Python (например, отсутствующий XML). В отличие от [play-tests.sh](../../Tools/qa/play-tests.sh), здесь нет ограничения времени процесса и явной проверки failed. Наличие ложного зелёного запуска на текущем Unity не установлено.

**Закрытие:** парсить XML, требовать завершённый непустой test-run без failed, сохранять ненулевой выход при отсутствии/повреждении XML, timeout и ошибке Unity. Проверить runner на коротких fixtures: успех, failed, пустой/битый/отсутствующий XML и ненулевой exit; не запускать Unity для теста одного shell gate.

## Что уже есть и не является открытым дефектом

- Разделены Core/Game/Platform/Editor и тестовые сборки; есть большой набор предметных EditMode/PlayMode и браузерных проверок.
- SaveService блокирует cloud writes до чтения, учитывает поколение аккаунта; защита локального NewerVersion уже добавлена. CG-RISK-004/005 не отменяют эти гарантии.
- В Endurance описаны исправления утечек материалов и PhysicsMaterial; не переносить старые before-failures в текущий backlog без повторного воспроизведения.
- Ghost v2 сохраняет полный поворот/время/разрывы и совместимость v1; это визуальный replay, не сетевой мультиплеер. Нет оснований требовать воспроизведения боя в рамках этой функции.
- Портретный режим исключён дизайном; отсутствие portrait не записано как дефект.

## Как поддерживать список и graphify

При изменении статуса сохранять ID, дату, конкретные источники и критерий закрытия. Для closed указывать проверенный snapshot и артефакт; запись из середины хронологического журнала не имеет приоритета над более поздним подтверждением. Полезные запросы: `graphify query "CG-RISK-001"`, `graphify query "CG-RISK-004"`, `graphify query "UnityProjectHealth"`.

Graphify обновлён адресно по этому документу, README.md, AGENTS.md и CLAUDE.md. Остальной граф сохраняет прежний срез кода и не объявляется полностью переиндексированным. `graphify-out/` исключён из Git; долговечный источник для восстановления рисков — этот Markdown. При переносе проекта индексировать документы семантически: code-only update не добавит их содержимое.
