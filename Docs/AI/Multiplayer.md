## 2. Что говорит Яндекс (проверено 2026-09-25)

Источники: `yandex.ru/dev/games/doc/ru/…` (`concepts/requirements` от 22.09.2026, `console/add-new-game`,
`sdk/sdk-multiplayer-sessions`, `sdk/sdk-player`, `sdk/sdk-purchases#signature`, `sdk/sdk-events`,
`sdk/sdk-server-time`, `sdk/sdk-config`, `concepts/languages-and-domains`, `requirements/4/4`), полный текст —
`llms-full.txt`. Заголовки хостинга сняты `curl -I` с игры 374739.

### 2.1. Реального мультиплеера в SDK нет

- **[факт]** Есть только асинхронный `ysdk.multiplayer.sessions`: `init({count ≤ 10, isEventBased,
  maxOpponentTurnTime, meta: {meta1..3: {min,max}}})` → `commit(payload)` во время игры → `push({meta1..3})`
  в конце. Сессия ≤ **200 КБ**, у события `time` = мс от начала игры **с вычетом пауз** (привязано к
  `GameplayAPI.start/stop`). Для загрузки чужих сессий нужен хотя бы один `meta` и `count > 0`, иначе только запись.
  Яндекс сам приводит гонки с «тенями» (Дикие Тачки 2) как целевой сценарий. У нас это уже сделано (M9, призраки).
- **[факт]** В требованиях к игре **нет пунктов про сеть, сервер, WebSocket и мультиплеер**. Запрета нет.
- **[факт]** `console/add-new-game`: «Мы рекомендуем хранить игры на сервере Яндекса. **Если игре нужна сложная
  серверная архитектура (например, для мультиплеера), вы можете подключить её через `iframe`.** Для этого напишите в
  чат поддержки: название игры, аккаунт разработчика, ссылку на игру (https), причину, по которой архив не подходит».
  При своём домене: SDK по абсолютному пути `https://sdk.games.s3.yandex.net/sdk.js`; игра должна открываться со всех
  доменов `yandex.{az,by,co.il,com,com.am,com.ge,com.tr,ee,fr,kz,lt,lv,md,ru,tj,tm,uz}` (+ `*.yandex.{tld}` в
  `frame-ancestors`, если есть CSP); на iOS `localStorage` может сбрасываться — использовать `safeStorage`.

### 2.2. CSP хостинга: сейчас только отчёт

- **[факт]** Архивные игры отдаются с `https://app-<id>.games.s3.yandex.net/<id>/<hash>/index.html`. Заголовок —
  `Content-Security-Policy-Report-Only` (не блокирующий), `connect-src 'self'` + только домены Яндекса
  (`games-sdk.yandex.*`, `mc.yandex.ru`, `an.yandex.ru`, `avatars.mds.yandex.net`, …), отчёты уходят в
  `csp.yandex.net`. Своего сервера там нет.
- **Вывод.** Соединение `wss://наш-сервер` из архивной игры **сегодня работает**, но каждое помечается нарушением и
  отправляется Яндексу. Если Яндекс переключит заголовок в блокирующий режим, мультиплеер из архива отвалится
  без предупреждения. Надёжные пути — iframe со своего домена или письменное подтверждение поддержки (§7).

### 2.3. Правила, которые меняют дизайн сетевой игры

| Пункт | Что требует | Следствие для нас |
|---|---|---|
| 1.2, 1.2.1, 1.2.2 | Вход только через Яндекс ID по кнопке с объяснением; гостевая игра с сохранением прогресса | Свой логин запрещён. Гость играет онлайн по `getUniqueID()`; авторизация — только ради подписи и имени |
| 1.14 | Нет ошибок и зависаний, в т. ч. при сворачивании, рекламе, истории браузера | Потеря связи, сворачивание вкладки и недоступный сервер не должны ломать игру: откат в одиночный режим/ботов |
| 1.14 + модерация | Игра должна дойти до геймплея у модератора | Матч не может ждать живых соперников вечно: боты занимают свободные места через N секунд |

| 4.7 | Во время полноэкранной рекламы звук и геймплей на паузе | Rewarded «продолжить» внутри сетевого матча невозможен — только в одиночных режимах |

### 2.4. Проверка игрока на своём сервере

- **[факт]** `ysdk.getPlayer({ signed: true })` → `player.signature` = `<подпись base64>.<данные профиля base64>`,
  HMAC-SHA256 с **секретным ключом игры**, в JSON есть `issuedAt`. Лимит `getPlayer` — 20 вызовов за 5 минут.
- **[факт]** Ключ появляется в консоли (Инап-покупки → Настройки) **только после подключения инап-покупок**.
  Без покупок сервер не может проверить подпись; тогда только `getUniqueID()` без гарантии подлинности.
- **[факт]** `ysdk.serverTime()` — доверенное время для суток и событий; для синхронизации тиков матча не годится
  (это время платформы, а не нашего сервера) — часы матча даёт наш сервер.
- **[факт]** `ysdk.getFlags()` — удалённые флаги из консоли, всегда с `defaultFlags`. Подходят для выключателя
  мультиплеера и адреса сервера без новой модерации.

### 2.5. Прочее

- **[факт]** В документации теперь есть раздел `sdk/unity` — это сторонний бесплатный PluginYG2 (max-games.ru),
  мультиплеера в нём нет. Наш мост (`YandexBridge.jslib` + `cars-platform.js`) остаётся.
- **[факт]** Прямых правил о ботах, выдаваемых за людей, нет. **[предложение]** Честно помечать ботов (значок),
  чтобы не нарушить 8.2.2 («материалы не вводят игрока в заблуждение») и не получить отзывы про «фейковый онлайн».

## 3. Варианты

| Вариант | Своя инфраструктура | Взаимодействие машин | Читы | Цена |
|---|---|---|---|---|
| A. Призраки через `multiplayer.sessions` (есть) | нет | нет, только поза | нет смысла | 0 |
| B. «Боевые призраки»: запись позы + выстрелов, чужой призрак в бою ведёт наш ИИ с его машиной и оружием | нет | с ботом-двойником, не с человеком | нет | 0, 200 КБ на сессию |
| C. Photon Fusion 2 Shared / Photon Realtime | облако Photon | да | клиент решает сам | плата за онлайн; привязка к их модели объектов |
| D. **Свой сервер: Unity без графики + Unity Transport (WebSocket)** | VPS в РФ, TLS | да | сервер решает | VPS; больше кода |

**[предложение] D** как цель, **B** как дешёвый шаг, который работает без сервера. Почему D, а не C:

- Симуляция уже тиковая и детерминированная по порядку (`SimulationDriver`), ввод — один `DriveCommand` с `Tick`,
  ИИ — те же `ICarInputSource`. Серверу достаточно запустить ту же сцену без графики.
- Физика на PhysX (`CarController`, Rigidbody) **не детерминирована** между устройствами и в WebGL — lockstep и
  откат с пересчётом отпадают. Нужен авторитетный сервер: он решает попадания, урон, мины, бонусы, финиш.
- Unity Transport (`com.unity.transport`; в Unity 6 встроенный, 6.5.0 для 6000.5) — официальный низкоуровневый транспорт: WebSocket
  в клиенте WebGL и на сервере Linux, надёжный конвейер, без объектной модели Netcode for GameObjects. Протокол свой,
  бинарный, под наши тики.
- Сервер в РФ (Yandex Cloud, Selectel) — задержка для основной аудитории.

## 4. Архитектура (D) [предложение]

### 4.1. Сервер

- Linux-плеер Unity с `-batchmode -nographics` (модуль Dedicated Server не установлен; для прототипа хватает
  обычного плеера, потом можно поставить модуль ради размера и CPU).
- Один процесс держит несколько комнат (по сцене на комнату или несколько трасс в одной физической сцене с разными
  `PhysicsScene`). Считает всех: людей, ботов, снаряды, мины, бонусы, `RaceDirector`.
- Снаружи TLS (`wss://`) через nginx/caddy перед процессом: страница Яндекса — https, `ws://` браузер не пустит.
- Origin: принимать `https://app-*.games.s3.yandex.net` (архив) или свой домен (iframe) и `localhost` для отладки.

### 4.2. Протокол

- Клиент → сервер: `DriveCommand` с номером тика, 50 Гц, пачкой последних 3–5 команд (потеря пакета не теряет ввод).
  Размер ~12 байт на команду.
- Сервер → клиент: снимок 20–30 Гц: для каждой машины поза, скорость, угловая скорость, здоровье, башня
  (yaw/pitch/цель из `CarCannon`), перезарядки и патроны `CarWeapons`, статусы `CarStatus`; события (выстрел, попадание,
  подбор, мина, смерть, финиш) — надёжным каналом.
- Часы: сервер задаёт тик старта и текущий тик; клиент держит свой тик чуть впереди сервера на половину пинга.

### 4.3. Клиент

- **Своя машина** считается у себя сразу (предсказание), расхождение со снимком гасится плавной подтяжкой, при
  большом — рывком. Полного отката с пересчётом нет: PhysX не перематывается дёшево.
- **Чужие машины** — кинематические, по интерполяции снимков с запаздыванием ~100 мс (как `GhostCar`, только из сети).
- Выстрел рисуется сразу, урон и смерть — только по событию сервера.
- `RaceClock` в матче берёт время с сервера; локальный `Time.maximumDeltaTime` роняет тики на лагах — в сети номер
  тика не может считаться локально.

### 4.4. Что меняется в коде

| Где | Что |
|---|---|
| Новое: `NetworkInputSource : ICarInputSource` | Команды игрока с сервера (на сервере) |
| `CarController`, `CarHealth`, `CarCannon`, `CarWeapons`, `CarStatus` | Выделить сериализуемое состояние снимка; применение снимка к кинематическому прокси |
| `Projectile`, `MineHazard`, `MineField`, `RaceDirector`, `PickupSpawner`, `OilHazardPool` | Появление и попадания решает только сервер; на клиенте визуал по событиям |
| `RngStreams` | Сид матча с сервера |
| `GameFlow` | Состояния «поиск», «лобби», отсчёт по серверу; награда за матч считается по результату сервера |
| `RaceSpawner` | Состав и раскраски машин из лобби |
| `RubberBand`, помощь отстающим | Выключены в PvP |
| `PauseController` | В матче пауза платформы не трогает `Time.timeScale` (§4.5) |

### 4.5. Пауза, вкладка, потеря связи

- `game_api_pause` (реклама не показывается в матче, но есть покупки, смена вкладки, сворачивание): звук выключен,
  ввод не шлётся, **машину на сервере ведёт `AiDriver`** до возврата. Мир не останавливается.
- Свёрнутая вкладка: браузер почти не крутит цикл Unity, соединение может остаться. Сервер через 2 с без команд
  переводит машину на автопилот, через 30 с без связи — снимает игрока (бот остаётся до конца матча).
- Возврат: полный снимок, продолжение. Потеря сервера: сообщение и возврат в меню без потери наград за прошлые матчи.

### 4.6. Подбор соперников

- Одна очередь на режим; через 8–10 с свободные места занимают боты (помечены). Модератор всегда доходит до игры.
- Уровень ботов — по рейтингу игрока, а не по сложности событий.

## 5. Этапы [предложение]

0. **Разрешение Яндекса** (§7) и прототип транспорта (§8): WebSocket из WebGL-сборки до сервера на Unity Transport.
1. **«Живые призраки»**: сервер только пересылает позы, без боя. Проверяет связь, задержку, подбор, модерацию и CSP.
2. **Бой на сервере**: попадания, урон, мины, бонусы решает сервер; своя машина всё ещё у себя.
3. **Полный авторитетный сервер**: машины считает сервер, у клиента предсказание своей машины, боты на сервере.
4. Параллельно, без сервера: **«боевые призраки»** (вариант B) — полезно, пока онлайна мало.

## 6. Риски

- Мало одновременных игроков в начале → почти всегда боты. Решение: боты в очереди + вариант B.
- Мобильный интернет и WebGL на слабых телефонах: снимки 20 Гц, дельта-сжатие, предел 8 машин в комнате.
- CSP из §2.2 может стать блокирующим. Решение: iframe со своего домена или подтверждение поддержки.
- Стоимость: VPS 2–4 vCPU держит, по грубой оценке, десятки комнат; мерить на этапе 1.

## 8. Прототип транспорта (2026-09-25)

Код: `Assets/CarsGame/Net/` — сборка `RacingGame.Net` компилируется **только при установленном `com.unity.transport`**
(`versionDefines` → `CARS_NET`). В основном `Packages/manifest.json` пакета нет, на игру код не влияет.

- `NetProtocol` — байт типа + поля: `Ping`, `Pong` (с числом пиров), `Relay` (≤ 1 КБ, пересылка всем остальным).
- `NetProbe` — клиент. Включается только `?net=ws://host:port/path` (или `wss://`) в URL страницы или
  `-netProbe <url>` в командной строке. Пинг 4 раза в секунду, «поза» 40 байт раз в секунду, отчёт `[NetProbe]` в лог.
- `RelayServer` — сервер без сцены и игрового цикла: `-executeMethod RacingGame.Net.RelayServer.RunFromCommandLine
  -netPort 7777 -netPath /net -netSeconds 600`. Годится и для пакетного редактора, и для Linux-плеера без графики.

**[факт] Проверено** на копии `/tmp/cars-qa/net` (сборка `BuildYandex`, шаблон Яндекса, `?sdk=mock`), сервер —
пакетный Unity 6000.5.9f1, страница отдавалась с **тем же `Content-Security-Policy-Report-Only`, что у хостинга
Яндекса** (без `report-uri`):

- **Пакет.** `com.unity.transport` в Unity 6 встроенный и привязан к версии редактора: вместо запрошенной 2.7.4
  встала **6.5.0** (`source: builtin`), других пакетов не тянет. API тот же, что в 2.x.
- **Сборка** проходит; wasm (сжатый) больше примерно на 0,3 МБ — оценка сверху, сравнение со вчерашней сборкой.
- **Две вкладки headless Chrome** подключились по WebSocket, сервер видит 2 пира, «позы» доходят от одной вкладки
  к другой (`relays in 11`), тест `PASS`.
- **CSP.** Chrome пишет в консоль нарушение `connect-src` для `ws://127.0.0.1:7777/net`, но соединение
  **не блокирует** — ровно то, что будет на хостинге Яндекса (и отчёт уйдёт в `csp.yandex.net`). Подтверждает §2.2.
- **Задержка привязана к кадрам.** В WebGL нет потоков: транспорт обрабатывается раз за кадр. Одна вкладка при
  16 FPS (программный рендер) — RTT в среднем 117 мс (мин 66) на localhost, это ~2 кадра; две вкладки при меньшем
  FPS — 95–1400 мс. Сервер отвечает мгновенно. Выводы для §4: при 60 FPS накладные расходы 17–33 мс;
  отправлять ввод сразу с `ScheduleFlushSend()` после `EndSend` (экономит кадр); сервер не должен ждать команды
  каждый тик — клиент шлёт пачку последних команд (§4.2); на слабых телефонах задержка растёт вместе с падением FPS.

Что дальше (этап 1): `wss://` через nginx/caddy с настоящим сертификатом, сервер как Linux-плеер без графики,
замер с реального телефона через мобильный интернет, затем «живые призраки» поверх `Relay`.
