## Save identity races

While awaiting the shared browser slot, review found two account-switch races. Both were reproduced before changing production code:

1. `SaveService` accepted an in-flight response for the previous identity, merged it and enabled writes to the new account without reading that account. New delayed-response tests cover initial load and retry/flush: **2 failures before the fix** (`save-before.xml`). Each load now captures an identity generation and rejects superseded responses before parsing, merging or authorizing writes.
2. In the WebGL adapter, a successful old write could clear the new account's queued save when its bytes were identical, losing that account's first upload. The logic-only Node VM probe reproduces this through the public boot/auth/queue/flush methods: **1/4 failed before**, **4/4 pass after** (`platform-save-{before,final}/evidence.json`). A write acknowledgement now checks both payload and identity generation. Old-account failures and changed payloads also remain covered. No browser, network or real account is involved in these unit scenarios.
